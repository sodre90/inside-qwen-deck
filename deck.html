Part I  How any LLM worksThe one idea

It predicts the next token. Then it does it again.

An LLM is a function. The input is all the text so far. The output is a score for every possible next piece of text. You pick one piece, append it, and call the function again.

That loop is the whole product. Answers, code and essays all come out one token at a time.

AnalogyYour phone keyboard's word suggestion, scaled up by a factor of a billion and given the whole conversation as input.
Step 1  Text becomes integersTokens

The model never sees letters. It sees tokens.

A tokenizer cuts text into pieces from a fixed list. Common words are one piece. Rare words split into several. Each piece has an integer ID.

Qwen3.8-Flash-Next's list has 248,320 entries. It covers many human languages, code, and special markers such as "end of turn" and "an image goes here".

Rule of thumb for English: one token is about three quarters of a word.

Step 2  Integers become vectorsEmbeddings

Each token becomes a list of 2,560 numbers.

The first layer is a plain lookup table: row token_id of a 248,320 x 2,560 matrix. That row is the token's embedding, a point in a 2,560-dimensional space.

Nobody chose those numbers. Training moved them until tokens used in similar ways ended up close together. Direction carries meaning.

AnalogyGPS coordinates, but with 2,560 axes instead of 2. Nearby points mean related things.
Worked example: a 4-word vocabulary, 3 numbers per word

Step 3  The one operation that mattersMatrix times vector

Almost everything is multiply, then add.

A weight matrix W turns one vector into another. Each output number is one row of W multiplied element by element with the input, then summed.

That is the core of every layer. The other steps (a squashing function, a normalization) are cheap next to it.

The dot product from the last slide is the same thing for a single row.

Worked example: a 2 x 3 matrix
Why we do thisA layer has to mix its inputs, giving some more weight than others. Matrix times vector does exactly that: each output is a weighted sum of all the inputs, and the weights are what training learned.Why it worksIt is the simplest operation that mixes everything with everything, and GPUs are built to do billions of these multiply-adds every second, in parallel.

Step 4  What "the model" actually isThe whole model as code

Twelve lines of loop and a lot of matrices.

The program is short. The weights are big: fixed matrices of numbers loaded from a file. Almost all the work is matrix times vector: multiply, add, repeat.

One expert matrix in this model is 640 x 2,560. The model has tens of thousands of them. Its routed experts alone hold about 121 billion numbers.

Hover or tap an underlined name in the code to see what it does.

Derived from the model config: 48 layers x 512 experts x 3 matrices x 640 x 2,560. The file on disk is smaller because each number is stored in about 4 bits instead of 16.

tokens = tokenize(prompt)
while True:
    x = embed[tokens]              # [n_tokens, 2560]
    for layer in layers:           # 48 of them
        x = x + mix_tokens(layer, x)  # attention: look at other tokens
        x = x + think(layer, x)       # feed-forward: work on each token
    scores = x[-1] @ lm_head         # [248320] one per vocab entry
    next = sample(softmax(scores / T))
    if next == END_OF_TURN: break
    tokens.append(next)

Step 5  Where the weights come fromTraining

Nobody writes the weights. They are tuned by trial and error.

Training starts with random numbers and a huge pile of text. The goal is the same game the model plays later: guess the next token.

AnalogyA mixing desk with billions of knobs. Play a sample, hear how wrong it sounds, nudge every knob slightly in the direction that sounds less wrong. Repeat trillions of times.

Knowledge in an LLM is not stored as records you can look up. It is spread across the weights as tendencies. That is also why it can state false things fluently.

Predict

Show the model "The capital of France is". Early in training it gives "Paris" only 3%.

Score the error

The error is how surprised the model was by the real next token. 3% is very surprised.

Nudge every weight

Calculus (backpropagation) tells each weight which direction lowers the error. Move each one a tiny step that way.

Repeat, then teach manners

After pre-training on raw text, a second stage trains on conversations and feedback so it answers questions instead of just continuing text.

Step 6  Inside the stackLayers and the residual stream

Each layer reads from a shared bus and adds its findings back.

Every token has a vector of 2,560 numbers that flows through all 48 layers. This is the residual stream. Each layer has two parts. One part moves information between tokens. The other part processes each token by itself. Both add to the stream; neither replaces it.

Worked example: a stream of 3 numbers through one layer
Why we do thisEach block only has to learn a small correction, not rebuild the whole vector.Why it worksNothing learned by earlier layers is lost, and during training the error signal flows straight back through the additions. That is what makes a 48-layer stack trainable.
stream in[1.0, 0.0, 2.0] + attention[0.1, 0.3, -0.2] → [1.1, 0.3, 1.8] + feed-forward[-0.4, 0.0, 0.5] → [0.7, 0.3, 2.3]

Nothing is overwritten. Each block adds a small correction. In the model each vector has 2,560 numbers.

Step 7  Moving information between tokensAttention

Attention is a fuzzy database lookup.

Every token makes three vectors from its stream: a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what do I hand over?").

A token compares its query with the key of every earlier token. Good matches get a high weight. The token then takes a weighted average of their values.

Tokens can only look backwards. The future has not been written yet.

AnalogySELECT value FROM earlier_tokens ORDER BY similarity(query, key), but every row contributes a little instead of one row winning.

Click a word to see where it looks. Weights are illustrative; a real model has many attention heads, each looking for something different.

Step 8  Choosing the next tokenSampling and temperature

The model gives odds. A dice roll picks the word.

The final layer outputs a raw score per vocabulary entry. Softmax turns scores into probabilities that add up to 100%. Then the sampler draws one.

Temperature divides the scores before softmax. Low temperature sharpens the odds toward the top choice. High temperature flattens them, so rare words appear more often.

This is why the same question can get different answers. It is also a setting, not a property of the model.

Step 9  Why long context is expensiveThe KV cache

Every token leaves a key and a value behind. Forever.

Keys and values of past tokens never change, so the engine stores them instead of recomputing. That store is the KV cache.

It grows with every token, in every attention layer. Each new token also has to compare against all of it. Long conversations cost memory and time.

This is the problem most of Part II is about.

KV cache at 200,000 tokens

Using this model's attention shape: 2 key/value heads x 256 numbers, 16-bit, keys plus values.

Part II  What makes this model differentOverview

Same loop. Six changes aimed at cost.

Qwen3.8-Flash-Next keeps the recipe from Part I. It changes where the work and the memory go, so that a large model runs at a small model's cost.

Mixture of experts512 small feed-forward networks per layer. Each token uses 10 of them, plus one shared expert.
Hybrid layers36 of 48 layers use Gated DeltaNet, a fixed-size memory. Only 12 keep a KV cache.
Sparse attention (QSA)The 12 full-attention layers read at most about 2,048 past tokens, chosen by a cheap index.
Hyper-connectionsSeveral residual streams instead of one, with learned mixing between them.
Phrase table (PLE)A 35.8 GiB lookup table keyed by a hash of the last few tokens, added to one layer.
Vision and draft headA vision encoder turns images into tokens. A draft head guesses several tokens ahead.
Change 1  Feed-forward layersMixture of experts

512 specialists per layer. Each token visits 10.

In a plain model, every token goes through the same big feed-forward network. Here that network is cut into 512 small experts per layer. A tiny router scores all 512 for the current token and runs only the top 10. One shared expert always runs as well.

So the model stores a lot of knowledge but uses about 2% of its experts per token. The model label is 125B-A6B: 125 billion weights in total, about 6 billion active per token. The routed experts are 2.4 billion of those 6. The rest runs for every token: the shared experts, the attention and DeltaNet layers, and the output matrix.

AnalogyA hospital with 512 specialists and a triage nurse. You see 10 of them, and a general practitioner who sees everyone.

Three of every four layers keep a fixed-size memory instead of a growing cache.

Change 3  The 12 full-attention layersQSA sparse attention

Read the index first. Then read only the pages that matter.

Even 12 full-attention layers get slow when every token compares against 200,000 others. QSA adds a cheap pre-filter.

  • Past tokens are grouped into blocks of 4.
  • A small indexer (4 heads x 128 numbers, much smaller than real attention) gives each block one score for the current token.
  • The top blocks, about 2,048 tokens worth, plus the newest unfinished block, go to real attention. The rest are skipped.
AnalogyAn index scan, then a bounded join. The expensive step reads a fixed budget, however large the table gets.

Change 4  The residual streamHyper-connections

More than one bus, with learned junctions.

Slide 8 showed one residual stream per token. Here each token carries several parallel copies of it. Before each block, a small learned mixer decides which blend of the copies to read. After the block, a second mixer decides how much of the result goes back into each copy.

This gives the network more room to keep separate kinds of information apart across 48 layers. In this model the mixers also take over the job of the usual normalization steps.

The number of parallel streams is a model setting (hc_count). The drawing shows four.

Worked example: 2 streams of 2 numbers (simplified)

Change 5  Cheap memorizationPLE n-gram hash embeddings

A 35.8 GiB phrase book, consulted by hash.

At each position, the model takes the short phrases that end there: the last 2 tokens, the last 3 tokens, and so on. It hashes each phrase to a row number and fetches that row from a very large table.

The fetched rows pass through a short filter and are added into one DeltaNet layer. No matrix math is needed to recall a common phrase. It is a memory lookup.

AnalogyA hash map from phrase to hint. Hash collisions are allowed; training learned to live with them.

Operational detail: the table is too big to keep in RAM next to everything else, so llama.cpp reads its rows from disk on demand. Long prompts can wait on the SSD here.

Worked example: a toy hash into a 1,000-row table
Why we do thisSome knowledge lives in phrases, not single tokens: "out of memory" means more than its three words. A row for every possible phrase would never fit, so a hash maps each phrase to one of a fixed number of rows.Why it worksIt is one memory lookup with no matrix math. When two phrases land on the same row, training learns to live with it: the filter damps unhelpful rows, and each phrase is looked up with several different multipliers, so one collision rarely spoils all of them.
token ids"of" = 315, "memory" = 4,217 (made-up ids) hash(315*7 + 4,217*13) mod 1,000 = (2,205 + 54,821) mod 1,000 = 57,026 mod 1,000 = 26mod keeps the row number inside the table (0 to 999), however big the ids get fetchrow 26 of the table, filter it, add it to the layer's input againsame for "out of memory" with different multipliers, and so on

The real hash uses large fixed multipliers, several hash heads per phrase length, and a table of 35.8 GiB.

Change 6a  Images as inputVision encoder

A picture becomes a row of tokens.

A separate vision network cuts the image into small square patches and turns each patch into a vector the size of a text token's. Those vectors go into the same sequence as the words. From there, the language model treats them like any other tokens. This vision encoder is the one from Qwen3-VL, unchanged.

Change 6b  Writing fasterMulti-token prediction (MTP)

Guess three words ahead, check them in one pass.

Writing is slow because each token needs a full trip through all 48 layers. The model ships with an extra small layer, a draft head, that cheaply guesses the next few tokens.

The full model then checks all the guesses in a single pass. Checking several tokens at once costs much less than producing them one by one. Correct guesses are kept; at the first wrong one, the full model's own answer is used instead.

The output is exactly what the full model would have written. Only the speed changes.

The draft head is optional. On this project's desktop the gain was small: checking 4 tokens touches more experts, and a 4-token pass took about twice as long as a 1-token pass. It also needs extra GPU memory.

Part III  Running itOne desktop, llama.cpp

Reading is fast. Writing waits on memory.

Reading the prompt (prefill) handles thousands of tokens at once. The GPU does big matrix-times-matrix work and stays busy.

Writing the answer (decode) handles one token at a time. Each token has to fetch its 10 experts per layer from memory, so speed depends on memory bandwidth, not arithmetic.

MoE is what makes a desktop possible. The experts are most of the file, and each token touches only a few, so they can live in cheaper system RAM. Weights are also stored at about 4 bits per number instead of 16.

  b. expertsThe router picks 10 of 512 experts plus the shared one.
  c. write backResults are added back into the streams for the next layer.
5. ScoreThe last vector becomes 248,320 scores; temperature and a dice roll pick "memory".
6. RepeatAppend the token. The draft head may have guessed the next few already.

Three things to remember

  • An LLM is a next-token predictor in a loop. Everything else is making that prediction good and cheap.
  • It does not look facts up. It generates what is likely. Check anything that matters.
  • Its only memory of your conversation is the context window. Nothing learns between chats.

What this model trades

  • Lots of storage (experts, phrase table) for little compute per token.
  • Exact attention in a quarter of the layers for flat cost in the rest.
  • A fixed attention budget for context lengths that would otherwise be unaffordable.
